# Integrated V1.1 Validation Report

## Scope

V1.1 is a targeted bugfix/resume release over Integrated V1.0. Frozen Phase 3 prompts and model-routing architecture are unchanged.

## Fix 1 — Phase 1 stale status reference

V1.0 could persist `status.image_optimized=false` even after the image had actually reached `FINALIZED`, because merge-safe `save()` replaced nested dictionaries while Phase 1 retained an older `status` reference.

V1.1 applies two defenses:

- Phase 1 reads/writes the live `data["status"]` mapping directly instead of caching `status` across saves.
- Metadata merge synchronization updates nested dictionaries in place, preserving live nested references even if a future caller caches one.

Regression coverage verifies that a captured status reference remains live across merge-safe saves and that `image_optimized=true` persists to disk.

## Fix 2 — `audit needed` manual PN resume

A prepared `output/*_canvas.png` or `*_regen.png` may be copied to `audit needed/` and renamed to the exact manually confirmed PN.

Safety / resume contract:

- SHA-256 must match an existing output candidate.
- The original `IMG_xxxx` source reference is recovered from the matched output filename.
- User filename is recorded as `USER_FILENAME_MANUAL_AUDIT` authority.
- No OpenAI precheck/regeneration/identity/OCR call is repeated.
- Deterministic canvas, logo overlay and final WebP are completed locally.
- Canonical metadata is renamed to the manually confirmed PN.
- Phase 2 is queued immediately; Phase 3 follows the normal Phase-2 terminal decision.
- Consumed audit files move to `audit needed/processed/`.
- Existing canonical Final images are never overwritten by a duplicate manual audit.

## Fix 3 — Integrated V1.0 checkpoint migration safety

When a previous V1.0 runtime is copied into V1.1, stale `status.image_optimized=false` no longer causes expensive Phase-1 replay. V1.1 accepts `image_optimization.status=completed` only when the recorded Final image exists on disk. If an old absolute path points at the previous repository, V1.1 can recover the copied `Final/<basename>.webp`, repair the canonical metadata locally, and mark Phase 1 completed without entering `process_one()` or making OpenAI calls.
